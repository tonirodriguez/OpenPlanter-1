# Analysis Plan: Recent Security Breaches Affecting Apple
Session: 20261009-215944-7dfb1b

## Objective
Find and document recent security breaches affecting Apple (approx. 2023–2026).

## Data Sources
- Primary: Web search (Exa) — news, official Apple security advisories, CISA, security vendor advisories.
- No local workspace datasets cover security breaches; all evidence is web-derived.

## Approach
1. Run broad web searches: "Apple security breach 2024", "Apple security breach 2025", "Apple security breach 2026", "Apple data breach iCloud", "Apple iCloud credential harvesting", "Apple supplier data breach".
2. Verify each lead with a second source (Apple Security Advisory, CISA KEV catalog, reputable security news).
3. Build entity-resolution-style record for each breach: name, date, type, impact, affected parties, source.
4. Flag unconfirmed/speculative claims explicitly.

## Cross-Reference / Linking Approach
Not applicable to cross-dataset linking (single web source). Each claim will cite specific URLs and dates; confidence tiers: confirmed (official advisory / multiple authoritative sources), probable (reputable media + corroborating vendor report), possible (single source / unconfirmed).

## Evidence Chain Construction
For each breach: claim → evidence (URL + date) → source → confidence.

## Expected Deliverables
- findings.md — human-readable report (summary + detailed evidence appendix).
- results.json — machine-readable structured findings.
- Wiki: new entry under `wiki/security/` (e.g., cisa-kev.md or security-breach-sources.md) documenting the breach sources used, linked from index.md.

## Risks & Limitations
- "Recent" is ambiguous; I'll cover 2024–2026 (and note older major incidents briefly).
- Some incidents are "near misses" or supplier-side breaches that did not compromise Apple core systems — these must be clearly distinguished from breaches of Apple services.
- Apple rarely discloses details; many reports are vendor-led. Confidence tiers apply.
